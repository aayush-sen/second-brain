---
name: venture-brief
description: Vet a business/product idea into a one-page brief with kill criteria. Use for "idea:", "vet this", "new venture", or advancing an existing venture page.
---

Read `os/OS.md` and `os/memory/preferences.md` first. Work only inside `os/`.

1. New idea → create `os/ventures/<kebab>.md` from `_template.md`, `status: spark`. Existing → read its record.
2. Dispatch the **scout** for the honest landscape: who already does this, how they distribute, what the hard part is, what a first customer looks like.
3. Write the brief into the record: one-line thesis, target user, distribution hypothesis, **explicit kill criteria**, next cheap experiment. Advance `spark → brief`.
4. Be honest per VISION.md: most ideas should die at brief. If the evidence says kill, recommend `killed` with the reason — that is the system working, not failing.
5. Log the record, append one episodic entry. Advancing past `brief` requires a real completed experiment, logged.
6. Session-end ritual per OS.md: uncertainties → `questions.md`, ideas → episodic `idea` line.
